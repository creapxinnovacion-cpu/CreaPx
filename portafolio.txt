# API Agente Contable 🚀

Este es el backend para la plataforma SaaS de contabilidad y procesamiento de Documentos Tributarios Electrónicos (DTE). Está construido bajo un enfoque moderno y modular utilizando **FastAPI**, **SQLAlchemy (ORM)** y validación estructurada basada en **Pydantic**. 

---

## 🏗️ Arquitectura del Proyecto

El proyecto está organizado usando una **Arquitectura Basada en Funcionalidades** (Feature-Based / Domain-Driven) aplicando el principio de *Colocation* (el código que cambia a la vez, vive junto):

* **`api/`**: Agrupa el código por dominios de negocio (ej. `auth`, `empresas`, `users`, `usuario_empresa`). Cada subcarpeta es independiente y contiene todo lo necesario para esa funcionalidad:
  * `model.py`: Esquema de persistencia mediante SQLAlchemy.
  * `schema.py`: Modelos Pydantic para validar entradas (*Requests*) y salidas (*Responses*).
  * `service.py`: Lógica de negocio pura y funcionalidad CRUD.
  * `router.py`: Exposición directa de los endpoints.
* **`db/`**: Configuración e instanciación de conexión a la base de datos. (Actualmente configurado con SQLite, listo para migrar a PostgreSQL/Neon).
* **`main.py`**: El corazón y punto de entrada de la aplicación FastAPI. Agrupa y registra los diferentes *routers*.
* **`seed.py`**: Script de inicialización rápida de datos de prueba en la base de datos.

---

## 🛠️ Instalación y Configuración

Asegúrate de contar con **Python 3.10+** instalado en tu sistema local.

1. **Clona o ubícate en el directorio matriz:**
   ```bash
   cd API-Agente-Contable
   ```

2. **Crea y activa el entorno virtual virtual:**
   * En Windows (PowerShell): 
     ```powershell
     python -m venv venv
     .\venv\Scripts\Activate.ps1
     ```
   * En Linux/Mac: 
     ```bash
     python3 -m venv venv
     source venv/bin/activate
     ```

4. **Instala los requerimientos definidos:**
   ```bash
   pip install -r requirements.txt
   ```

5. **Configura tus variables de entorno:**
   * Renombra o copia el archivo `.env.example` a `.env` en la raíz del proyecto.
   * Abre `.env` y sustituye la variable `DATABASE_URL` por la cadena de conexión real de NeonDB:
   ```env
   DATABASE_URL="postgresql://usuario:password@host-de-neon.aws.neon.tech/neondb?sslmode=require"
   SECRET_KEY="TU_CLAVE_SECRETA_PERSONALIZADA"
   ```

## 🛡️ Autenticación y Seguridad (JWT)

El sistema ya implementa un flujo de seguridad en producción:
- **Hash de Contraseñas:** Integración de la biblioteca `passlib[bcrypt]` en el servicio `auth_service.py` para encriptar los passwords antes de guardarlos a la BD.
- **Emisión de Tokens:** Endpoint `/auth/login` activo. Valida credenciales con la BD e instancia un *JSON Web Token* utilizando `python-jose`. 
- **Payload JWT Personalizado:** El token fue modelado no solo para portar la autorización, sino para inyectar vitalidad en el Frontend. Lleva intrínseco el rol (`is_admin`), el ID de la tabla `Empresa`, y crucialmente el `nitEmpresa`, que es consumido por las interfaces de React para su lógica de autodetección.

## 📡 Uso de la API y Ejemplos de Peticiones

La API se ejecuta localmente usando la URL base: `http://127.0.0.1:8000` (o el puerto que asigne uvicorn). A continuación se muestran ejemplos prácticos de cómo consumir los endpoints utilizando métodos HTTP, como por ejemplo desde React usando `fetch`.

### 1. Petición POST (Ejemplo: Iniciar Sesión)
El método **POST** se usa para *enviar información* al servidor (para crear recursos o autenticarse). Los datos suelen ir empaquetados en un Body (cuerpo) JSON.

**Router:** `/auth/login` (Definido en `auth.py`)

**Ejemplo con `fetch` en JavaScript:**
```javascript
fetch("http://127.0.0.1:8000/auth/login", {
  method: "POST",
  headers: {
    "Content-Type": "application/json"
  },
  body: JSON.stringify({
    email: "admin@creapx.com",
    password: "admin123"
  })
})
.then(response => response.json())
.then(data => console.log("Token JWT recibido:", data))
.catch(error => console.error("Error:", error));
```

*(Nota: Enviar credenciales como POST Body es lo ideal en lugar de pasarlos por Query Params)*.

### 2. Petición GET (Ejemplo: Obtener Listado de Empresas)
El método **GET** se emplea para *solicitar y leer* información del servidor.

**Router:** `/empresas/` (Definido en `empresa.py`)

**Ejemplo con `fetch` en JavaScript:**
```javascript
fetch("http://127.0.0.1:8000/empresas/", {
  method: "GET",
  headers: {
    "Content-Type": "application/json"
    // "Authorization": "Bearer TU_TOKEN_AQUI" // Agregarlo si la ruta requiere estar autenticado
  }
})
.then(response => response.json())
.then(data => console.log("Lista de empresas:", data))
.catch(error => console.error("Error:", error));
```

### 3. Petición DELETE (Ejemplo Formativo)
El método **DELETE** se utiliza para *eliminar un recurso* específico del sistema.
*(Nota temporal: Los routers como `empresa.py` o `users.py` actualmente solo tienen endpoints POST y GET, pero la estructura recomendada para un DELETE futuro es la siguiente):*

**Router:** `/empresas/{id}` -> Ej: `/empresas/1`

**Ejemplo con `fetch` en JavaScript:**
```javascript
fetch("http://127.0.0.1:10000/empresas/1", {
  method: "DELETE",
  headers: {
    "Content-Type": "application/json",
    "Authorization": "Bearer TU_TOKEN_AQUI" // Rutas destructivas DEBEN ser protegidas
  }
})
.then(response => {
    if(response.ok) {
        console.log("Empresa ID 1 eliminada correctamente");
    }
})
.catch(error => console.error("Error:", error));

# 🏥 Frontend - Panel Médico de Control e Impresión

Este es el cliente frontend del sistema médico. Proporciona una interfaz web premium con un diseño moderno de tipo **glassmorphism** (efecto de vidrio), radial-gradients oscuros y animaciones interactivas para gestionar pacientes, citas y generar recetas médicas en PDF de alta fidelidad.

---

## 🛠️ Tecnologías Utilizadas

- **HTML5**: Estructura semántica para la accesibilidad y optimización de SEO.
- **CSS3 (Vanilla)**: Diseños, layouts adaptativos y animaciones basadas en variables CSS de última generación.
- **Bootstrap 5**: Componentes estructurados, rejillas y modales adaptativos.
- **FontAwesome 6**: Iconografía médica y de control administrativo.
- **SweetAlert2**: Modales de confirmación interactivos y notificaciones en forma de Toast.
- **html2pdf.js**: Motor del lado del cliente que renderiza y descarga elementos DOM a archivos PDF con alta nitidez (escala 2.5x).

---

  - `styles.css`: Estilos de la interfaz de vidrio, colores de badges, botones flotantes y los estilos especiales para la impresión y exportación a PDF de la receta médica.
- `Js/`:
  - `api.js`: Centraliza las llamadas Fetch HTTP hacia la REST API del Backend, inyectando los tokens JWT.
  - `auth.js`: Controla el ciclo de sesión, roles de administrador y redirecciones.
  - `patients.js`: Renderizado del listado de pacientes, sincronización, edición y coloreado inteligente de expedientes.

  - `receta.js` **[NUEVO]**: Lógica de llenado del modal de receta médica, autocompletado y renderizado del PDF/Impresión.

# Sistema de Control de Inventario de Botiquín (React + Google Sheets)

Este es un sistema web premium diseñado en React con TypeScript y Vanilla CSS, estructurado bajo buenas prácticas de Clean Code, para administrar el inventario físico y financiero de un botiquín. La base de datos es en tiempo real y se conecta mediante Google Apps Script directamente a un libro de cálculo de Google Sheets.

Adicionalmente, el proyecto cuenta con soporte de dockerización, orquestación local con Docker Compose, despliegue en Kubernetes mediante Kustomize y un pipeline de Integración Continua (CI) con GitHub Actions.

---

## 🚀 Características Principales

1. **Gestión de Catálogos**: Registro y control de medicamentos (catálogo de productos), proveedores oficiales y usuarios operadores del botiquín.
2. **Control de Lotes**: Registro exacto de lotes individuales, costo unitario, cantidad inicial, cantidad actual, fecha de compra y fecha de vencimiento.
3. **Flujo Operativo Híbrido (FEFO + PEPS)**:
   * **FEFO (First Expired, First Out - Operación)**: Sugiere despachar del lote con fecha de vencimiento más cercana para evitar la merma de fármacos.
   * **PEPS (Primeras Entradas, Primeras Salidas - Contabilidad)**: Valora financieramente el egreso y consumo contable basándose en los costos de los lotes más antiguos comprados primero.
4. **Dashboard y Resumen Gerencial**: Tarjetas con indicadores interactivos y gráficos SVG que reflejan en tiempo real el valor total del inventario, consumo, compras del mes, lotes activos y alertas críticas.
5. **Panel Inteligente de Alertas**:
   * **Stock Crítico**: Alerta si el consolidado total de unidades de un medicamento es menor a su stock mínimo definido.
   * **Vencimientos**: Alerta preventiva (menos de 90 días), crítica (menos de 30 días) y alerta de lotes vencidos (bloqueados para el despacho).
6. **Auditoría Transaccional**: Registro técnico de operaciones (CREATE, UPDATE, DELETE) directo en la hoja `AUDITORIA` de Google Sheets.

---

## 🔄 Flujo de Trabajo (Workflow)

```mermaid
graph TD
    A[Inicio: Proveedor y Medicamento creados] --> B[Registrar Compra / Entrada]
    B --> C[Se crea Lote con Costo, Fecha Compra y Vencimiento]
    C --> D[Stock se incrementa]
    D --> E[Módulo Despacho: Seleccionar Producto]
    E --> F[Sistema ordena Lotes por FEFO: Vence antes -> Sale primero]
    F --> G[Sistema calcula Costo Contable por PEPS: Comprado antes -> Valora costo]
    G --> H[Confirmar Despacho / Salida]
    H --> I[Se reduce stock del lote físico en LOTES]
    H --> J[Se registra movimiento en MOVIMIENTOS_INVENTARIO con costo PEPS]
    H --> K[Se desglosa lote afectado en DESPACHOS]
    H --> L[Se registra log en AUDITORIA]
```

### 1. Proceso de Abastecimiento (Al Comprar)
1. Ingrese a la pestaña **Registrar Compra**.
2. Seleccione el medicamento y el proveedor.
3. Defina el código único de lote (ej: `L-PARA-2026A`).
4. Ingrese la cantidad de unidades compradas y su costo unitario neto.
5. Establezca la fecha de vencimiento e ingrese notas del documento de compra si es necesario.
6. Haga clic en **Registrar Compra**:
   * Se crea una fila en la hoja `LOTES` con `cantidad_actual = cantidad`.
   * Se crea un movimiento tipo `COMPRA` en `MOVIMIENTOS_INVENTARIO` para alimentar el gráfico de flujos y compras del mes.

### 2. Proceso de Distribución (Al Despachar)
1. Ingrese a la pestaña **Registrar Despacho**.
2. Seleccione el medicamento a entregar (solo se listan productos con stock disponible).
3. Escriba la cantidad solicitada.
4. **Propuesta del Sistema (FEFO + PEPS)**: El sistema generará una caja de sugerencia detallando:
   * **FEFO Físico**: Los lotes específicos de los que se tomará el medicamento, priorizando los que expiran primero.
   * **PEPS Contable**: El desglose de costos imputando el precio unitario del lote que se compró primero históricamente.
5. Indique quién despacha (operador activo) y el nombre de la persona o departamento receptor.
6. Presione **Confirmar Despacho**:
   * Se descuenta el stock físico de los lotes seleccionados por FEFO en la hoja `LOTES`.
   * Se añade una entrada en `MOVIMIENTOS_INVENTARIO` con tipo `DESPACHO` y con el valor unitario imputado por el cálculo PEPS contable.
   * Se registra el desglose físico detallado en la hoja `DESPACHOS`.
   * Se registra log en `AUDITORIA`.

## 📖 Guía de Módulos y Páginas

A continuación se detalla el propósito, funcionamiento y un ejemplo de uso de cada una de las pestañas que integran el sistema de control del botiquín:

### 1. 📊 Panel General (Dashboard)
* **📌 Propósito (¿Para qué sirve?):** Ofrece una visión general en tiempo real del estado de abastecimiento y la salud financiera del botiquín mediante indicadores clave (KPIs), gráficas interactivas y un panel inteligente de alertas críticas.
* **⚙️ ¿Cómo funciona?:** Consolida y analiza las existencias en la base de datos para calcular:
  * **Valor del Inventario:** Costo total acumulado de todos los lotes activos (unidades disponibles × costo unitario).
  * **Consumo del Mes:** Sumatoria del costo contable de todos los despachos registrados en el mes actual.
  * **Alertas de Stock Mínimo:** Identificación automática de productos cuya cantidad física total es menor que el stock de seguridad configurado.
  * **Alertas de Expiración:** Clasificación de lotes por proximidad a vencer en tres niveles: Vencidos (bloqueados automáticamente para el despacho), Alerta Crítica (vence en menos de 30 días) y Alerta Preventiva (vence en un rango de 30 a 90 días).
  * **Gráfico SVG de Flujo:** Tendencia visual de las compras vs. egresos de los últimos meses.
* **💡 Ejemplo Práctico:** Al iniciar la jornada, el farmacéutico entra a la aplicación y en el Panel General observa una alerta en rojo: *"¡Stock Crítico! Ibuprofeno 400mg tiene 10 unidades disponibles (Mínimo: 15)"* y otra en amarillo: *"¡Alerta Preventiva! Lote L-PARA-03 de Paracetamol con 40 unidades vence en 45 días"*. Esto le indica inmediatamente que debe tramitar una orden de compra de Ibuprofeno y priorizar el despacho de ese lote de Paracetamol.

### 2. 📦 Inventario Físico (Catálogo e Inventario)
* **📌 Propósito (¿Para qué sirve?):** Centraliza el catálogo maestro de medicamentos permitiendo su creación, edición, borrado lógico y el desglose en tiempo real de lotes y unidades físicas de cada producto.
* **⚙️ ¿Cómo funciona?:** Muestra una tabla compacta con todos los medicamentos. Al hacer clic en un producto, se expande un panel que detalla los lotes activos asociados (fecha de compra, costo unitario, cantidad inicial y cantidad remanente). Además, incluye un formulario interactivo para agregar nuevos productos con la opción de dar de alta un lote inicial de forma simultánea.
* **💡 Ejemplo Práctico:** Para registrar un medicamento que nunca antes ha estado en inventario, vas a la pestaña **Inventario Físico**, haces clic en **Nuevo Producto**, rellenas el nombre *"Loratadina 10mg"*, categoría *"Antihistamínicos"*, y activas la casilla *"Registrar lote inicial"*. Completa los campos con cantidad *50*, costo unitario *0.20 USD*, lote *L-LORA-01* y fecha de vencimiento *2028-05-15*. Al guardar, el producto queda ingresado en el catálogo y su lote listo para ser despachado.

### 3. 🛍️ Registrar Compra (Abastecimiento de Lotes)
* **📌 Propósito (¿Para qué sirve?):** Permite ingresar nuevos lotes de productos existentes en el catálogo para reabastecer el stock, registrando la trazabilidad del proveedor y los costos del lote.
* **⚙️ ¿Cómo funciona?:** A través de un formulario estructurado, el usuario selecciona un medicamento del catálogo y un proveedor autorizado. Posteriormente, indica el código único del lote (para rastreo de vencimientos), la cantidad de unidades, el costo unitario de adquisición y la fecha de expiración. Al confirmar, el sistema suma las existencias al lote y genera una transacción tipo `COMPRA` en el historial contable.
* **💡 Ejemplo Práctico:** El proveedor *Droguería Médica S.A.* entrega una caja de *Paracetamol 500mg*. En la pestaña **Registrar Compra**, seleccionas *Paracetamol 500mg*, seleccionas el proveedor, escribes el lote de fábrica *PAR-2026B*, ingresas cantidad *200*, costo unitario *0.15 USD*, y fecha de vencimiento *2029-01-10*. Tras pulsar *"Registrar Compra"*, el inventario global de Paracetamol se incrementa inmediatamente en 200 unidades asociadas a este nuevo lote.

### 4. 🚚 Registrar Despacho (Despacho de Medicinas)
* **📌 Propósito (¿Para qué sirve?):** Gestiona la entrega física de medicamentos a pacientes o departamentos internos bajo reglas de control físico y contabilidad financiera automatizadas.
* **⚙️ ¿Cómo funciona?:** El usuario selecciona el medicamento y la cantidad a despachar. El motor de la app genera al instante una propuesta dual:
  1. **FEFO Físico (First Expired, First Out):** Indica de qué lote(s) específico(s) deben tomarse las unidades físicas (priorizando los más próximos a expirar para evitar merma).
  2. **PEPS Contable (Primeras Entradas, Primeras Salidas):** Determina el costo financiero del despacho, calculándolo con base en el costo unitario de las unidades más antiguas que ingresaron al botiquín.
  El usuario selecciona al operador que despacha, escribe el nombre del receptor e ingresa la justificación médica. Al guardar, se descuentan las unidades físicas de los lotes correspondientes y se registra un egreso tipo `DESPACHO` con el valor calculado por PEPS.
* **💡 Ejemplo Práctico:** Una enfermera solicita *30 unidades* de *Ibuprofeno 400mg*. En inventario hay dos lotes: el lote `IBU-A` (vence en julio de 2026, costo $0.30, con 20 unidades) y el lote `IBU-B` (vence en diciembre de 2026, costo $0.35, con 100 unidades). Al ingresar la cantidad de 30:
  * El sistema propone retirar físicamente: *20 unidades de IBU-A* y *10 unidades de IBU-B* (FEFO).
  * El sistema calcula el costo contable: *(20 x $0.30) + (10 x $0.35) = 9.50 USD* (PEPS).
  Se completa el registro a nombre de la enfermera receptora y se presiona *"Confirmar Despacho"*.

### 5. 👥 Proveedores (Directorio de Proveedores)
* **📌 Propósito (¿Para qué sirve?):** Administra el directorio de contactos oficiales de las droguerías, farmacéuticas y distribuidores que surten al botiquín.
* **⚙️ ¿Cómo funciona?:** Muestra una interfaz limpia con tarjetas o listas que resumen el nombre de la empresa, persona de contacto, teléfono y correo electrónico. Cuenta con un formulario sencillo para dar de alta nuevos proveedores y un botón para dar de baja (desactivar lógicamente) a aquellos con los que ya no se opere.
* **💡 Ejemplo Práctico:** Deseas registrar un nuevo distribuidor de vacunas. Ingresas al módulo de **Proveedores**, haces clic en **Agregar Proveedor** y rellenas el formulario: Nombre: *Distribuidora Farma-Vida*, Contacto: *Ing. Luis Pineda*, Teléfono: *2233-4455*, Email: *ventas@farmavida.com*. A partir de ese momento, *Distribuidora Farma-Vida* aparecerá como opción elegible en la pantalla de reabastecimiento/compras.

### 6. 📜 Historial y Auditoría (Kardex, Auditoría y Ajustes)
* **📌 Propósito (¿Para qué sirve?):** Garantiza la máxima transparencia y control interno. Registra el Kardex de inventario completo, guarda bitácoras técnicas de cambios y permite la conciliación de discrepancias mediante ajustes físicos.
* **⚙️ ¿Cómo funciona?:** Se divide en tres sub-paneles clave:
  * **Kardex (Movimientos):** Historial cronológico detallado de todos los ingresos (`COMPRA`), egresos (`DESPACHO`) y ajustes del botiquín.
  * **Auditoría:** Logs técnicos del sistema que indican la fecha exacta, el usuario operador y la acción CRUD realizada en el Google Sheets.
  * **Ajustes de Inventario:** Formulario que permite igualar el stock del sistema con el stock real contado en físico en caso de pérdidas, vencimientos no detectados o errores de digitación. Modifica directamente las cantidades en la tabla de lotes y genera un movimiento tipo `AJUSTE`.
* **💡 Ejemplo Práctico (Ajuste):** Durante la auditoría de fin de mes, se descubre que en el estante físico quedan *48 tabletas* de *Loratadina* del lote *L-LORA-01*, pero el sistema indica que hay *50* (dos se dañaron por humedad). El operador va a la pestaña **Historial y Auditoría**, abre el formulario de **Ajuste de Inventario**, selecciona el lote *L-LORA-01*, coloca la cantidad nueva de *48* y escribe en el motivo *"Mermas por daño físico / humedad"*. El sistema corrige las existencias a 48 y guarda el registro del ajuste para justificación administrativa.

### 7. ⚙️ Configuración (Ajustes de Enlace Cloud)

* **⚙️ ¿Cómo funciona?:** Ofrece una caja de texto para guardar la URL de la aplicación web de Google Apps Script. Cuenta con una opción para realizar pruebas de comunicación (ping-pong) para verificar que no haya problemas de red o CORS. Adicionalmente, cuenta con un listado para agregar usuarios y asignarles roles para la firma de despachos y compras.

### Actualización del Apps Script en Google Sheets
Para que la aplicación pueda consultar los registros, es imperativo actualizar la función `doPost(e)` de su archivo Google Apps Script para dar soporte a la acción `read`.

Pegue el siguiente switch en su editor de Apps Script reemplazando el `doPost` original:

```javascript
function doPost(e) {
  try {
    const body = JSON.parse(e.postData.contents);
    const action = body.action;
    const sheetName = body.sheet;
    const usuario = body.usuario || "SYSTEM";

    validateSheet(sheetName);

    switch (action) {
      case "read":
        return jsonResponse(getAll(sheetName));
      case "create":
        return jsonResponse(createRecord(sheetName, body.data, usuario));
      case "update":
        return jsonResponse(updateRecord(sheetName, body.uuid, body.data, usuario));
      case "delete":
        return jsonResponse(deleteRecord(sheetName, body.uuid, usuario));
      default:
        throw new Error("Acción inválida");
    }
  } catch (err) {
    return jsonResponse({
      success: false,
      message: err.message
    });
  }
}
```

## 🛠️ Componentes Principales de la Aplicación

La aplicación se divide en tres ventanas principales, dependiendo del estado de la licencia y cómo el usuario inicia el sistema.

Esta es la primera ventana que verás al ejecutar la aplicación por primera vez en un equipo nuevo. 
- **Propósito:** Validar la licencia del producto y asociar la aplicación a tu cuenta de usuario.
- **Campos requeridos:**

  - Solo se descargarán facturas de los correos agregados a esta lista de confianza.
